# План рефакторинга провайдера Kinopoisk

## Основная задача
Создать унифицированный интерфейс для сервисов кинопоиска, добавить новую реализацию с API `https://kinopoiskapiunofficial.tech/` и дать пользователю возможность выбирать провайдера в настройках.

## Задачи

### 1. Создание унифицированного интерфейса
- [ ] Создать интерфейс `IKinopoiskProvider` с базовыми методами
- [ ] Определить общие типы данных для всех провайдеров
- [ ] Создать абстрактный базовый класс `BaseKinopoiskProvider`

### 2. Рефакторинг текущей реализации
- [ ] Привести текущий `KinopoiskService` к новому интерфейсу
- [ ] Переименовать в `KinopoiskDevProvider`
- [ ] Обеспечить совместимость с существующим кодом

### 3. Создание нового провайдера
- [ ] Изучить API `https://kinopoiskapiunofficial.tech/`
- [ ] Создать `KinopoiskUnofficialProvider`
- [ ] Реализовать все методы интерфейса
- [ ] Добавить обработку ошибок

### 4. Система выбора провайдера
- [ ] Добавить настройку выбора провайдера в `AppSettings`
- [ ] Создать фабрику провайдеров `KinopoiskProviderFactory`
- [ ] Обновить компонент настроек
- [ ] Добавить поля для API ключей разных провайдеров

### 5. Интеграция и тестирование
- [ ] Обновить все компоненты для работы с новой системой
- [ ] Добавить валидацию API ключей для каждого провайдера
- [ ] Протестировать переключение между провайдерами
- [ ] Добавить обработку ошибок и fallback механизмы

## Чек-лист выполнения
- [ ] Задача 1: Создание унифицированного интерфейса
- [ ] Задача 2: Рефакторинг текущей реализации
- [ ] Задача 3: Создание нового провайдера
- [ ] Задача 4: Система выбора провайдера
- [ ] Задача 5: Интеграция и тестирование

## Архитектурные принципы
- Использование паттерна Strategy для выбора провайдера
- Соблюдение принципов SOLID
- Модульная архитектура с четким разделением ответственности
- Единообразный интерфейс для всех провайдеров
- Возможность легкого добавления новых провайдеров в будущем
